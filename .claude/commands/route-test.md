`/route`가 작업을 올바른 서브에이전트에 보내는지 확인합니다. 인자: $ARGUMENTS

## 모드

- **dry (기본)**: 분류만 합니다. 서브에이전트를 호출하지 않으므로 비용이 들지 않습니다.
- **run**: 네 서브에이전트를 실제로 한 번씩 호출해 각자 자기 모델 이름을 답하게 합니다. 비용이 들 수 있으므로 사용자가 `run`을 명시했을 때만 합니다.

## 샘플 작업 (기대 결과)

| # | 작업 | 기대 서브에이전트 |
|---|---|---|
| 1 | 이 함수가 어디서 쓰이는지 찾아줘 (`minigames-engine/src/lib/score.ts`의 export 사용처) | haiku-worker |
| 2 | 달고나 점수 계산에서 오타 난 변수명 하나 고쳐줘 (정답이 정해진 한 줄 수정) | haiku-worker |
| 3 | 팽이 돌리기에 최고 회전 속도 표시 UI를 추가하고 테스트를 작성해줘 | sonnet-worker |
| 4 | 엔진·게임·홈 세 패키지에 걸친 공통 결과 화면 구조를 설계하고 대안을 비교해줘 | opus-architect |
| 5 | Opus로 두 번 고쳤는데도 간헐적으로 실패하는 터치 끊김 버그의 원인을 찾아줘 | fable-expert |

## dry 모드 절차

1. `.claude/commands/route.md`의 분류 순서를 다시 읽습니다.
2. 샘플 1~5 각각에 대해 ①→④ 순서로 분류하고, 선택한 서브에이전트를 적습니다. 서브에이전트를 호출하지 않습니다.
3. 아래 표로 결과를 보고합니다.

| # | 기대 | 실제 분류 | 결과 (일치/불일치) | 근거 한 줄 |
|---|---|---|---|---|

4. 불일치가 있으면 어느 분류 규칙이 잘못 걸렸는지 `route.md`의 해당 줄을 가리켜 설명합니다. 고치기 전에 사용자에게 확인합니다.

## run 모드 절차

1. `haiku-worker`, `sonnet-worker`, `opus-architect`, `fable-expert` 네 서브에이전트를 Agent 도구로 각각 한 번씩 호출합니다. 프롬프트는 "파일을 읽거나 고치지 말고, 당신이 실행 중인 모델의 이름만 한 줄로 답하세요."로 고정합니다.
2. 각 응답을 기대 모델과 비교합니다. 기대: haiku-worker → Haiku, sonnet-worker → Sonnet, opus-architect → Opus, fable-expert → Fable.
3. 표로 보고합니다.

| 서브에이전트 | 기대 모델 | 응답 | 결과 |
|---|---|---|---|

4. 응답이 기대와 다르거나 서브에이전트가 목록에 없으면 "연결 실패"로 표시하고, 세션을 새로 열어 `/agents`로 목록을 확인하도록 안내합니다.

## 공통 규칙

- 테스트 중에는 파일을 만들거나 고치지 않습니다. 커밋과 push도 하지 않습니다.
- 샘플 작업 목록을 바꾸려면 이 파일의 표를 고칩니다. 실제 작업 파일에 있는 내용을 섞지 않습니다.
- 명령은 세션을 시작할 때 읽히므로, 이 파일을 만들거나 고친 뒤에는 새 세션에서 실행합니다.
