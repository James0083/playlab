# 모델 선택 지침 (Claude Code · VSCode)

기본 모델은 `.claude/settings.json`에서 Sonnet으로 고정돼 있다.
작업을 맡길 때는 **`/route <작업>`** 명령을 쓴다. 명령이 작업을 분류해 네 모델 중 맞는 서브에이전트에 자동으로 넘긴다.

| 서브에이전트 | 모델 | 맡기는 작업 |
|---|---|---|
| `haiku-worker` | Haiku 5.5 | **간단한 작업 전부:** 파일 1~2개 조회, 한 줄 수정, 위치·사용처 찾기, 로그·목록 요약, 포맷 변환 |
| `sonnet-worker` | Sonnet 5.5 | 기능 추가, 버그 수정(원인 명확), 테스트, 한 게임 안의 변경, 문서 갱신 |
| `opus-architect` | Opus 5.5 | 여러 패키지에 걸친 설계, 대규모 리팩토링 계획, 여러 갈래 원인 분석, 설계 대안 비교 |
| `fable-expert` | Fable 5.1 | Opus로도 막힌 최고 난이도 문제, 출시 전 전체 점검 |

## 모델별 판단 기준

- **Haiku**: 간단한 일. 파일 1~2개, 한 곳 조회, 한 줄 수정, 요약·정리. 간단하면 무조건 Haiku. 가장 싸고 빠르다.
- **Sonnet**: 간단하지 않은 일상 개발(여러 파일을 깊게 고치는 기능·버그·테스트). 애매하다는 이유로 Sonnet을 고르지 않는다.
- **Opus**: 파일 여러 개, 패키지 여러 개가 얽히거나 설계 결정이 필요할 때.
- **Fable**: Opus가 두 번 시도해도 못 푼 문제, 또는 품질이 비용보다 중요한 최종 검토. 일상 작업에는 쓰지 않는다.

Anthropic 권장: Sonnet을 기본으로 두고, 부족하면 Opus, Opus도 실패하는 좁은 경우에만 Fable.
Mythos는 일반 사용 대상이 아니므로 고려하지 않는다.

## 자동 위임 흐름

1. `/route`가 작업을 분류하고, 어떤 모델에 맡기는지 한 줄로 알려준다.
2. 해당 서브에이전트가 작업하고 결과를 보고한다.
3. 서브에이전트가 막히면 한 단계 위 모델로 **한 번만** 다시 맡긴다(haiku → sonnet → opus → fable).

## 규칙

- 모델과 관계없이 프로젝트 규칙(CONVENTIONS.md, 커밋 전 `pnpm check`, 의존성 정책)을 지킨다.
- 서브에이전트는 커밋과 push를 하지 않는다. 커밋은 사용자가 요청할 때만 한다.
- effort(생각의 양)는 쉬운 작업에 높게 주지 않는다. 높은 모델 + 중간 effort가 총비용이 낮은 경우가 많다. effort 설정 키는 버전마다 다르므로 공식 문서를 확인한다.
- 작업 하나의 **총비용**으로 판단한다. 단가만 보면 싼 모델이 유리해 보이지만 재시도가 쌓이면 역전된다.

## 파일 구성

- `.claude/settings.json`: 기본 모델(Sonnet)
- `.claude/CLAUDE.md`: 이 지침
- `.claude/commands/route.md`: `/route` 명령
- `.claude/agents/*.md`: 네 서브에이전트(모델 고정)
- `.claude/settings.local.json`: 개인 설정(git에 올리지 않음)
